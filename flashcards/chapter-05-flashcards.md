## Chapter 5: Address Clustering, Co-Spend Heuristics, and Entity Attribution — Flashcards

| # | Front (Question) | Back (Answer) |
|---|-----------------|---------------|
| 1 | What does the common-input-ownership (co-spend) heuristic assume? | All inputs to a single non-CoinJoin transaction are controlled by the same entity, since spending requires the private keys for every input. Exam tip: this is the foundational heuristic behind address clustering. |
| 2 | Who first formalized the common-input-ownership heuristic in academic literature, and when? | Meiklejohn et al., 'A Fistful of Bitcoins' (2013). Exam tip: the same paper introduced change-address heuristics used alongside co-spend clustering. |
| 3 | What transaction pattern breaks the common-input-ownership heuristic? | CoinJoin-style transactions where multiple unrelated parties combine inputs into one transaction, typically producing many equal-value outputs. Exam tip: high input/output count with identical output values is the CoinJoin signature. |
| 4 | Name two change-address heuristics used after co-spend clustering. | 1) One-time-address heuristic — change output has never appeared on-chain before. 2) Optimal-change heuristic — the non-round-number output is more likely change than the round-number payment output. Exam tip: neither is 100% reliable individually. |
| 5 | How does address clustering differ from entity attribution? | Clustering groups addresses believed to be controlled by one wallet/entity using on-chain heuristics (technical). Attribution assigns a real-world name (exchange, service, individual) to that cluster using off-chain data (investigative). Exam tip: clustering ≠ identification. |
| 6 | List the four sources of off-chain attribution data. | 1) Scraping (public forum posts, exchange deposit pages) 2) KYC leaks (breached exchange databases) 3) Voluntary disclosure (entity self-publishes addresses) 4) Direct engagement (subpoenas/legal requests to entities). Exam tip: know which requires legal process. |
| 7 | Which attribution source requires formal legal process such as a subpoena? | Direct engagement with a regulated entity (e.g., an exchange), typically via law enforcement request. Exam tip: this is the only source of the four that necessarily involves legal compulsion. |
| 8 | What is a 'peel chain'? | A sequence of transactions where a large balance is repeatedly split — a small amount 'peels off' to a payment address while the remainder moves to a new change address each hop. Exam tip: common in exchange withdrawal fan-out and layering/money-laundering activity. |
| 9 | Tool-agnostic: how do cluster-visualization tools like Reactor typically represent clusters? | As graph nodes representing clusters/entities, connected by edges representing transactions, often with size or color encoding balance or risk score. Exam tip: the exam tests the underlying concept, not vendor-specific UI details. |
| 10 | Can address clustering alone prove legal ownership of funds? | No — clustering only establishes probabilistic technical control. Legal/real-world identity requires separate attribution evidence. Exam tip: common trap is conflating clustering confidence with identity confidence. |
| 11 | What output pattern is the strongest red flag that a transaction is a CoinJoin? | Many equal-value outputs paired with a large, roughly equal number of inputs from otherwise-unrelated clusters. Exam tip: analysts should exclude such transactions from naive common-input clustering. |
| 12 | Why does address reuse matter for both clustering and attribution? | Reuse strengthens co-spend clustering confidence (same entity spending again) and increases the chance the address has been scraped, leaked, or voluntarily disclosed, aiding attribution. Exam tip: address reuse is a privacy failure actively exploited by analysts. |
